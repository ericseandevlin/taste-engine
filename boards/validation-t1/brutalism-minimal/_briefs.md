# Brutalism-Minimal Validation Briefs

Six synthetic HTML exemplars for the brutalism-minimal strand (the raw-HTML lineage of
Craigslist, link-aggregator front pages, and mailing-list archives). Each brief describes a
real-world genre of site that ships information first and never dresses it up. None of these
should read as "clean" or "designed." They should read as pages built by people who cared
about the data, not the presentation. None should cosplay a terminal or a CRT either, this is
honest default HTML rendered by an ordinary browser, not a costume of an older medium.

## 1. Metro Classifieds Index

A city classifieds hub, structured like a folder of typed index cards someone put online.
Top-level categories (housing, jobs, for sale, services, community, personals) each expand
into a flat list of dozens of one-line postings with a date stamp and a neighborhood tag. No
photos. No summaries beyond the headline itself. Nearly unstyled: default body font, a
handful of horizontal rules to separate categories, underlined blue links throughout. The
only concession to design is that the categories are broken into lists instead of one giant
paragraph.

## 2. Ranker (link aggregator front page)

A ranked front page of outbound links submitted by users, in the vein of the old
link-aggregator boards: numbered rows, each with a title link, the linked domain in
parentheses, and a meta line underneath (points, submitter, age, comment count, each its own
link). Built with a plain HTML table for row structure and column alignment, because that is
the honest way to line up a rank number against a title against a score. Dense: thirty ranked
links on the front page, no excerpt text, no thumbnails.

## 3. Faculty Homepage, Dept. of Statistics

A single professor's personal page, hand-coded and untouched in a decade. Sections for a
short bio, research interests, a long numbered publication list (title, co-authors, venue,
year, PDF link), a table of courses taught this term, and office hours as a plain paragraph.
Times New Roman throughout, because nobody ever set a font-family. No imagery at all. This is
the strand's "never got around to styling it" register, but it should still read as a
working page, not a broken one.

## 4. Statistical Computing Mailing List Archive

A monthly archive index for a technical mailing list, auto-generated by list software: a
table of Date, Subject, and Author for every message that month, with reply subjects indented
to show threads. Monospace typography throughout, since the archive generator assumes
fixed-width alignment matters more than typographic polish. Dense: forty-plus message rows
across a handful of threads, with links to individual messages that do not need to resolve
(fragment anchors are fine).

## 5. Restaurant Equipment Exchange

A used-equipment swap board for commercial kitchen gear: a dense table of listings (item,
condition, price, location, seller contact, date posted) with visible cell borders throughout.
A plain search form sits at the top: a text input, a category select, a submit button, all
native controls, none of them styled. No photos; a "photo on request" note stands in for
imagery. This is the strand's crude-table-layout register: the table is obviously doing
layout duty as well as holding data, and nobody smoothed that over.

## 6. Fairview Community Events Board

A town bulletin board listing upcoming events (library talks, church suppers, little league
sign-ups, town hall meetings) grouped by week. Each entry is one dense line: date, time,
title, location, contact. Default system sans-serif, blue underlined links only where an
event has an external sign-up link, thin horizontal rules between weeks. No hero, no icons,
no calendar graphic, just a long list a volunteer maintains by hand.

---

Traps avoided across all six: none use a refined grid, generous curated whitespace, or a
considered type scale, that would tip into designed minimalism rather than brutalism. None
use green-on-black monospace, scanlines, or CRT framing, that would tip into terminal
retro cosplay rather than honest current-medium defaults. The plainness in every page comes
from shipping information as directly as possible, not from adopting a look.
